## High priority findings

1. **97.4% is answerability precision, not evidence-span accuracy.** `scripts/eval_end_to_end.py:97-104` counts any accepted answer on an answerable question as a true positive, even if the extracted span is wrong. Recomputed PDF counts: 380 accepted, 370 on answerable questions, 363 overlapping gold. Thus 370/380 = 97.4% answerability precision, 363/380 = 95.5% accepted-span overlap precision, and 363/443 = 81.9% span-hit recall. Report sections 6 and 7, evaluation measure definitions, and slide 16 should stop calling 97.4% the fraction of answers that are real evidence. The calibration's 95.3% refers to CUAD-text overlap, a different measure and input path. Keep these definitions distinct. The F0.5 threshold also optimizes answerability, not span correctness.

2. **The rewrite gate does not enforce all the faithfulness scores it computes.** `jargonaut/checks.py:167-185` only gates on backward NLI coverage, number sets, and presence of a negation cue. It computes but ignores forward support and contradiction. A controlled stub returning coverage 0.9, support 0.1, and contradiction 1.0 still passes when the number/negation checks pass. This verifies gate logic, not the probability of a real NLI failure. Consider a validation-tested support/contradiction rule and substantive human review; do not tune the gate on test outcomes. The saved PDF rows also contain 13 check-passing rewrites whose extracted spans do not overlap gold: rewrite checks cannot establish retrieval correctness.

3. **The report overstates protection from bad rewrites.** The abstract says checks keep reversed meanings from reaching the user. This is not guaranteed by these heuristics, and `static/index.html:270` explicitly offers “Show the rewrite that failed the checks.” Say the original clause is the default response for flagged rewrites and the rejected rewrite remains inspectable. Claim only that the checks caught the documented example, not all reversals.

4. **18.9 to 8.3 is generated-output readability, not the average displayed answer.** `scripts/eval_end_to_end.py:226` averages all 380 generated rewrites, including the 176 withheld ones. With each rejected rewrite replaced by the original clause, the mean of the saved per-answer FKGL values is approximately 13.33. Label 8.3 as pre-gate rewrite FKGL; optionally report the displayed-output mean and passing-only mean separately. This is a mean of individual scores, not a score on concatenated text. Applies to the report abstract, section 6.5, and slide 13.

5. **Assignment provenance needs resolving.** Guidelines page 1 excludes LLM APIs. The evaluation document states that two Claude agents labelled the fictional set and an agent generated router questions; the report contains related TODOs. This does not establish which interface was used or prove a violation. Record the actual tools/interfaces used for synthetic training pairs, labels, questions, and code assistance, and obtain course clarification where needed. Do not represent agent agreement as independent human validation. Kappa 1.0 does not establish label correctness.

6. **The runnable-submission requirement is unfinished.** Guidelines page 2 explicitly allocates marks to preprocessing/training/testing instructions and runnable code. Report section 5 is entirely TODOs, while the missing assets above block reproduction. The report also omits known extractor hyperparameters that can already be filled from the notebook: 3 epochs, learning rate 1e-5, train batch 8, accumulation 4 (effective 32), inference batch 16, max length 512, stride 128, seed 42, 3 hard negatives, weight decay 0.01, and 10% warmup. Current settings are ten categories with synthetic extractor questions disabled. These are code settings, not independently verified metadata for absent weights.

## Code and packaging issues

13. **Number and negation checks are weaker than their descriptions.** `checks.py:58-89` compares sets of digit strings, ignoring units, roles, repetition, and associations. A probe changing “30 dollars within 12 days” to “12 dollars within 30 years” retains perfect number recall. Moving a negation from Seller to Buyer retains `negation_kept=1`. “Eighteen” is absent from the number-word mapping and falsely fails against “18”; confirmed in a pure-function probe. Describe these as lexical heuristics. Extend them with targeted regression cases if changing them, and version/re-evaluate rather than silently changing previously reported results.

14. **Custom extractor path can load mismatched settings.** `extractor.py:51` calls `deberta_settings()` without passing its constructor's `run_dir`; that helper reads global `DEBERTA_RUN`. A caller supplying another run loads its weights but the default run's threshold/token cap. Make settings read from the same explicit run directory. Default Docker use is not affected.

15. **Gemma prediction cache can silently reuse another configuration.** Generation cell in `gemma_evaluation.ipynb` loads any existing `results/<split>/predictions.csv`, without validating dataset hash, adapter, prompt, model revision, or generation settings. The README tells users to delete it, but the code does not enforce this. Add a configuration fingerprint and reject stale caches before comparing runs.

16. **Label freezing has a line-ending portability issue.** Exact hashes pass for gold.jsonl and gold_a.jsonl; gold_b.jsonl, questions.jsonl, and labeling_guide.md match only after CRLF-to-LF normalization. This is consistent with line-ending conversion, not evidence of label edits. Document a canonical hashing rule and enforce line endings. The hash manifest itself cannot prove chronological independence of annotation and evaluation.

17. **Topic routing discards question specifics.** `pipeline.py:110-113` substitutes the standard CUAD question after routing. All questions routed to one category retrieve/extract against the same query, regardless of party, condition, or subquestion. The simplifier rewrites the clause rather than directly answering those specifics. Disclose this scope. The lightweight dialogue manager exists (clarification, active topic, “anything else”), so resolve the report's implementation TODO, but do not imply general contextual follow-up understanding.
